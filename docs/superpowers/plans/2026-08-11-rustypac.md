# RustyPac Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and safely activate a bytehaul-backed pacman downloader with resumable transfers, adaptive one-line progress, graceful signal handling, and targeted enable/disable configuration.

**Architecture:** A small async Rust binary separates CLI/configuration, transfer ownership, per-output locking, signal control, progress reduction, and terminal rendering. Pacman supplies one URL and exact `.part` output per process; bytehaul owns HTTP transfer mechanics while RustyPac owns lifecycle policy and presentation.

**Tech Stack:** Rust 1.97.1; bytehaul 0.2.0; Tokio; unicode-width; terminal_size; libc; Rust unit/integration tests with tempfile and local TCP/HTTP fixtures.

## Global Constraints

- Linux/Arch/CachyOS target; executable name is exactly `RustyPac`.
- CLI forms are exactly `RustyPac URL OUTPUT`, `RustyPac --enable`, and `RustyPac --disable`.
- Pacman owns mirror selection, signature policy, and final `.part` rename.
- Output must remain usable by `DownloadUser = alpm`.
- No aria2 fallback, daemon, GUI, mirror manager, package manager, unknown-length resume, or connection-count display.
- Never modify live pacman configuration until all non-live gates pass.
- Use Red → Green → Refactor for every task and record meaningful results in the current implementation journal.

---

## File map

- `Cargo.toml`: package, exact binary name, runtime and test dependencies.
- `src/main.rs`: process entrypoint and exit-code mapping.
- `src/cli.rs`: argument classification and dispatch types.
- `src/config.rs`: narrow pacman.conf analysis and atomic enable/disable edits.
- `src/download.rs`: bytehaul setup, event loop, output validation, and outcome classification.
- `src/lock.rs`: per-output ownership record and stale-lock recovery.
- `src/signals.rs`: Unix signal stream and lifecycle commands.
- `src/progress.rs`: renderer-independent transfer display model and units/time formatting.
- `src/render.rs`: responsive layouts, Unicode width, color state, throttling, and terminal writes.
- `tests/http_transfer.rs`: local HTTP range/fallback/error/resume integration tests.
- `tests/terminal_render.rs`: pseudo-terminal redraw, resize, color, and newline checks.
- `tests/signals.rs`: process signal, pause/continue, and stale-state checks.
- `tests/config_cli.rs`: fixture-based interactive enable/disable checks.
- `tests/alpm_gate.rs`: ignored privileged compatibility check run explicitly as `alpm`.
